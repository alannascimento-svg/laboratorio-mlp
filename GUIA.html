Consultar ou importar não inicia treinamento.

PCA não transforma resultados históricos retroativamente; uma avaliação com PCA exige nova execução. Modelos anteriores continuam sem PCA e seus arquivos permanecem preservados.

Múltiplas classes e base de proteínas

O importador reconhece o TXT Protein Localization Sites, separa seu texto introdutório e mostra ID, oito medidas e classe. Os 1.484 registros e os valores originais são preservados. As contagens vêm da tabela: EXC tem 35 casos, apesar de a introdução dizer 37.

A regra geral é H = teto((entradas + saídas) / 2). Para proteínas: 8 entradas → 9 ocultos ReLU → 10 saídas Softmax. Cada saída representa uma classe, em ordem gravada no modelo. A sigmoide ainda não foi aplicada. O caso M/B mantém a ordem [M,B] e os códigos 10/01.

Outras classes usam K-fold estratificado por grupos. Registros com o mesmo ID ou medidas idênticas ficam no mesmo grupo, sem compartilhá-lo entre treino, validação e teste. A base exige ao menos 50 registros e cinco grupos por classe. ERL tem cinco exemplos: para esta base, use K-fold 5. O teste externo não escolhe pesos, normalização, momentum nem época.

Precisão, recall e F1 usam média macro entre classes. As quatro métricas também aparecem como média ± STD amostral entre folds, separadas do resultado OOF global. A matriz de confusão, os pesos, as previsões e a memória de cálculo mostram todas as classes do modelo.

Compatibilidade: os exemplos e regras M/B nas seções abaixo descrevem o protocolo binário original. Modelos antigos mantêm suas classes e sua interpretação; nenhum histórico é convertido ou sobrescrito. Consulte também o README.md para instalação e verificações da edição pública.

Rede neural educacional para classificação binária B/M. O projeto roda no computador, em CPU, com painel no navegador. O motor é implementado explicitamente com NumPy: uma camada oculta ReLU, duas saídas Softmax, backpropagation e atualização SGD com momentum. Adam continua disponível para comparar com a versão anterior.

Não usar para diagnóstico, triagem ou decisões clínicas. O experimento original recebe medidas numéricas WDBC, não imagens, e não foi validado clinicamente. Um escore Softmax não é uma probabilidade clínica calibrada.

2. A arquitetura agora é uma fórmula

A regra definida para este projeto é:

D = quantidade de características numéricas de entrada
S = 2 saídas, na ordem [M, B]
H = teto((D + S) / 2)
Arquitetura = D → H → S
Parâmetros treináveis = (D + 1) × H + (H + 1) × S

“Teto” significa arredondar para cima quando o resultado não é inteiro. É uma convenção explícita para completar a regra. Não é uma fórmula universal que garanta o melhor desempenho de uma MLP.

Entradas D Cálculo de H Ocultos H Rede
20 (20 + 2) / 2 11 20–11–2
30 (30 + 2) / 2 16 30–16–2
31 teto(33 / 2) 17 31–17–2
32 (32 + 2) / 2 17 32–17–2
40 (40 + 2) / 2 21 40–21–2

Logo, 30–16–2 não está errado: é o resultado da fórmula nesta base. O erro da implementação anterior era fixar esses números. Agora o carregamento, as matrizes, o treinamento, a serialização, a previsão e a visualização respeitam D.

Em 30–16–2 existem 480 pesos W1, 16 vieses b1, 32 pesos W2 e 2 vieses b2: 530 parâmetros. O ID não é entrada e o diagnóstico é somente o alvo. A soma 30 + 2 usada para dimensionar H não transforma as saídas em entradas.

Base fornecida e CSVs com outras dimensões

O TXT original contém documentação e registros sem cabeçalho; esse formato continua exigindo 30 medidas, para não aceitar silenciosamente uma linha WDBC incompleta.

Para outro número de características, use CSV com cabeçalho obrigatório:

id,diagnosis,medida_a,medida_b,medida_c
amostra_001,M,1.2,3.4,5.6
amostra_002,B,2.1,4.3,6.5

Este trecho ilustra o formato, não é uma base suficiente para treinar. O protocolo implementado exige no mínimo 50 registros e 20 exemplos de cada classe, de 1 a 256 medidas, nomes únicos, valores numéricos finitos e IDs únicos. diagnosis deve conter B ou M. Nomes reservados de ID/diagnóstico não podem ser usados como medidas. IDs e vetores de medidas repetidos são rejeitados para revisão antes da divisão.

O sistema não determina se cada linha representa uma pessoa independente. A independência e a qualidade dos rótulos precisam ser verificadas pelo responsável pela base. As classes genéricas usam grupos de IDs ou medidas idênticas; isso não identifica automaticamente pessoas relacionadas ou outros vínculos ausentes na tabela.

3. Backpropagation não é concorrente de Adam

MLP é a arquitetura. Backpropagation é o cálculo das derivadas do erro em relação aos pesos, pela regra da cadeia. SGD com momentum e Adam são métodos diferentes para usar essas derivadas e atualizar os parâmetros. Ambos podem utilizar backpropagation. A versão anterior já calculava essas derivadas; nesta versão o método de atualização padrão mudou para SGD com momentum.

O fluxo de um lote é:

1. Entrada padronizada Z
2. Z1 = Z × W1 + b1
3. H = ReLU(Z1)
4. logits = H × W2 + b2
5. scores = Softmax(logits)
6. erro = entropia cruzada + regularização L2 dos pesos
7. backpropagation: derivadas de W2, b2, W1 e b1
8. atualização dos pesos pelo otimizador escolhido

A Softmax é calculada de forma numericamente estável. Para um lote com N amostras e alvos one-hot Y, a derivada nos logits é (scores − Y) / N. A retropropagação da camada oculta multiplica pela matriz W2 transposta e pela derivada ReLU. O WTA é usado na decisão final, não como função diferenciável de aprendizado.

Ordem das saídas: [M, B]. Portanto M = [1,0] = código 10; B = [0,1] = código 01. Em empate exato, argmax escolhe M por convenção registrada, não por uma regra clínica. Ao importar os CSVs em planilhas, trate os códigos como texto para preservar o zero inicial de 01.

4. Momentum e o sinal do gradiente

No SGD implementado:

v(t) = μ × v(t−1) − η × g(t)
w(t) = w(t−1) + v(t)

η é a taxa de aprendizado, μ é o coeficiente de momentum, g é a derivada calculada pela backpropagation e v é a atualização acumulada. Os vieses seguem a mesma atualização.

Gradiente negativo não é erro. Sem momentum, para η = 0,01 e g = −0,4, a atualização é −ηg = +0,004. Aumentar esse peso pode reduzir a perda. Não buscamos tornar todas as derivadas positivas. O gradiente é um vetor de componentes; sua norma, um indicador de magnitude, é sempre não negativa.

A frase “acelerar quando o gradiente ficar negativo para voltar a positivo” não foi implementada literalmente. Foi substituída, explicitamente, por uma heurística experimental de momentum limitado, baseada na perda e no alinhamento de gradientes completos de treino entre épocas. Não é RPROP, Nesterov ou um método com garantia de convergência.

Regra adaptativa exata

Ao final de cada época, o programa recalcula o gradiente da função objetivo no conjunto completo que está sendo usado para treinar naquela fase. A referência inicial é o gradiente antes da primeira época. O alinhamento é:

c = produto_escalar(g_atual, g_anterior) / (norma(g_atual) × norma(g_anterior))

Quando alguma norma é zero, o alinhamento é definido como zero. Os sinais de componentes isoladas não comandam a adaptação.

Condição ao final da época Alteração para a próxima época
Perda diminuiu além da tolerância e c > 0 μ = mínimo(μ máximo, μ + incremento)
Perda aumentou além da tolerância OU c < 0 μ = μ × fator de redução; zera a velocidade
Demais casos Mantém μ
Modo momentum fixo Mantém sempre μ inicial

“Perda” nessa regra é a entropia cruzada de treino com a penalidade L2. A curva principal mostra a entropia cruzada sem L2; os dois valores estão registrados. O teste externo e os rótulos do teste não participam da adaptação. A validação interna escolhe a duração, separadamente.

A primeira época usa μ = 0,10. A taxa η não muda automaticamente. No modo Adam, os controles de μ não têm efeito: Adam usa seus próprios momentos, com β1 = 0,9 e β2 = 0,999. O painel indica essa distinção.

5. Partições, Z-score e ausência de repetição no teste

O modo principal preserva a regra combinada: primeira rodada com aproximadamente 10% de teste, demais blocos entre 10% e 20% do total original, sorteados com restrição de viabilidade para não sobrar um grupo minúsculo. Os blocos são estratificados por classe e não se repetem no teste de uma mesma execução. Foram mantidos também os modos K-fold de 5 e de 10 grupos aproximadamente iguais.

Na semente 42 da base fornecida, os testes têm 57, 62, 101, 94, 82, 81 e 92 registros. Cada caso é testado uma única vez. Um caso que foi teste em uma rodada pode ser treino em outra, mas cada rodada começa com rede, estado do otimizador e normalizador novos.

A média e o desvio-padrão Z-score são calculados exclusivamente no treino pertinente. Característica constante recebe escala 1. Na seleção interna, o normalizador usa apenas o subtreino interno. Depois de escolhidas as épocas, o normalizador e os pesos são reiniciados e ajustados com todo o treino externo; somente então o teste externo é avaliado. A mesma lógica interna é usada para o modelo final treinado em toda a base.

Os grupos de teste não são usados para escolher duração, momentum, escala ou pesos. O modelo final não herda pesos da rodada de maior acurácia e não tem um teste independente posterior ao ajuste completo.

6. Destaques e comparação honesta

O painel destaca maior acurácia, maior sensibilidade e maior F1 nas execuções comparáveis, incluindo todos os empates. Nas rodadas, evidencia os melhores valores de acurácia e sensibilidade. Os demais indicadores continuam visíveis; os arquivos JSON de destaques também incluem especificidade, F1 e menor quantidade de falsos negativos.

A comparação entre execuções exige a mesma base por SHA-256, o mesmo modo e as mesmas partições internas e externas. Diferentes bases não entram no mesmo ranking. Trocar a semente normalmente muda as partições e cria outro grupo de comparação. Reexecutar um modelo com a mesma semente é teste de reprodutibilidade, não evidência independente adicional.

O ranking é exploratório. Escolher hiperparâmetros repetidamente pelo melhor resultado OOF pode superestimar desempenho. Uma avaliação final após essa escolha requer dados independentes ou validação aninhada que também contenha a busca de hiperparâmetros. Os pequenos blocos não são concursos diretamente equivalentes: por isso a acurácia global usa todas as previsões OOF, não a melhor rodada nem a média simples de porcentagens.

7. Visualizar a rede e seus pesos

Na aba Rede e pesos reais, selecione a execução, o modelo final ou uma rodada, e o checkpoint. A vista pode mostrar o modelo concluído, a inicialização ou as épocas periódicas da seleção interna e do retreino.

Clique em H01, H02 etc. para destacar as conexões daquele neurônio. As linhas azuis são pesos positivos e as terracota são negativos; espessura representa magnitude. Isso não significa “benigno versus maligno”. Passar o mouse mostra o valor da conexão, e o painel apresenta os vieses e todos os parâmetros em tabela, CSV ou JSON. O arquivo NPZ preserva os valores de ponto flutuante; a tela arredonda a apresentação.

W1[i,j] conecta a entrada i ao neurônio oculto j. W2[j,k] conecta o oculto j à saída k. b1 e b2 são os vieses. Na rede de referência são 512 conexões e 18 vieses. Peso isolado não é medida causal de importância de uma característica, especialmente em uma composição não linear.

A inspeção interativa está na aba Rede e pesos reais do painel. A demonstração incluída contém os parâmetros do novo exemplo público.

8. Tudo o que é guardado

Cada treinamento usa uma pasta exclusiva em resultados/. O código recusa pasta de saída não vazia. Não existe rotina que apague os resultados ruins ou mantenha apenas o melhor.

resultados/rDATA_HORA_microsegundos/

  rodadas.csv / metricas_oof.json / destaques_rodadas.json
  previsoes_oof.csv / erros_oof.csv / particoes_auditoria.csv
  historico_treinamento.csv
  folds/fold_01/.../modelo.npz, pesos.csv, indices.json, normalizacao.csv
  folds/fold_01/checkpoints/selecao_interna/...
  folds/fold_01/checkpoints/retreino/...
  checkpoints_final/selecao_interna/...
  checkpoints_final/retreino/...
  modelo_final.npz / pesos_final.csv / rede_final.json
  modelo_final_selecao.csv / modelo_final_treinamento.csv
  modelo_final_metadados.json / modelo_final_indices.json
  normalizacao_final.csv / modelo_previsao.csv / comparacao.json
  inferencias/pDATA_HORA_identificador/entrada.csv, previsoes.csv, metadados.json

Em cada fase, as métricas são acrescentadas a historico.jsonl a cada época e ultimo.npz é atualizado. Os arquivos epoca_00000.npz, epoca_00025.npz etc. preservam estados numerados. Também ficam salvos o estado selecionado e a época escolhida mesmo quando ela não é múltipla do intervalo. Para guardar todas as épocas separadamente, coloque intervalo 1; o uso de disco aumenta.

O log contém taxa de aprendizado, μ usado e próximo, perda com/sem L2, norma e alinhamento do gradiente e fração de componentes negativas. Falhas tratadas preservam os artefatos existentes e marcam status de erro. Encerramento forçado ou falta de energia pode deixar a execução marcada como em andamento; os arquivos já escritos permanecem, mas isso não é garantia contra perda física do disco.

Checkpoints são para inspeção, não para retomada exata do treinamento. Estados de velocidade/Adam e posição do embaralhamento não são restaurados nesta versão. Uma nova execução começa do zero. O aplicativo não faz backup externo automático: exporte a execução ou copie a pasta para outro disco/armazenamento seguro.

As previsões feitas pelo painel e pelo CLI são automaticamente arquivadas junto com a entrada e a identificação SHA-256 do modelo. O programa só confirma o salvamento quando as gravações terminam. Ao usar dados próprios sensíveis, proteja também a pasta de resultados, pois ela contém uma cópia da base utilizada.

9. Linha de comando

Dentro do ambiente virtual:

python treinar.py --dados dados/cancear.txt --otimizador sgd_momentum \
  --momentum-inicial 0.10 --momentum-maximo 0.90 \
  --incremento-momentum 0.01 --fator-reducao 0.50 \
  --taxa 0.001 --epocas 800 --seed 42 --salvar-cada 25

Em Windows, use a linha toda sem as barras de continuação. Para μ fixo, acrescente --momentum-fixo. Para comparar o otimizador anterior, use --otimizador adam. python treinar.py --help mostra todos os controles.

python prever.py --modelo resultados/IDENTIFICADOR/modelo_final.npz --entrada minhas_medidas.csv
python -m unittest discover -s tests -v

O CSV de inferência precisa das mesmas medidas nomeadas do modelo; permite ID opcional, não permite diagnóstico. Nomes são usados para reordenar as colunas. Não basta ter a mesma quantidade de números: o significado e o nome de cada característica devem corresponder ao treinamento.
